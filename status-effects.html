    A status effect is a timed effect attached to a hero or an enemy: damage over time such as Bleed, Poison and Burn, stat debuffs such as Corrosion, control effects such as Stun, and every buff from a potion or skill (see Buffs and Shields and protection). The game shows them only as small icons with a fill bar above a health bar. This page explains the shared machinery: how the gauge fills, how long an effect lasts, how two effects of the same type interact, what resistance actually does, and how to get rid of them.

    Overview#

    Every status is one row of the status table (ES_StatusData, 124 rows). The row picks one of 26 logic kinds (LogicType, a small Lua class Status<kind>.lua) and fills in five parameters, a duration, a build-up rate and some flags. The game has no English names for statuses; the names on this wiki translate the designers' internal labels.

    FieldMeaning for players
    StackAddPerBuild-up added per application, in % of the gauge. 100 or more means the status starts at once ("instant").
    StackSubPerHow fast an unfinished gauge drains, in % per second.
    StackSubDelaySeconds after the first application before draining starts (0, 0.1, 0.2 or 0.5; the Poisons, Burns and Corrosion use 0.2, most Bleeds use 0).
    TimeDuration in seconds once active (999 = rest of the fight, 0 = until removed).
    IsRefreshHitting an active status restarts its timer.
    OverlayMaximum stacks (0 = does not stack).
    StatusTypeThe family. Two statuses of the same family cannot coexist.
    IsDebufferCounts as a debuff: blocked by debuff immunity, removed by cleansing.
    IsShowWhether the icon is shown at all.
    Param1...Param5, AttackType, DefenceTypeThe numbers the kind uses (see Damage over time formula).

    The build-up gauge#

    1. The first application creates the status at StackAddPer %. The icon appears with a partial fill.
    2. Each further application adds StackAddPer again.
    3. Starting StackSubDelay seconds after the first application, the gauge drains continuously at StackSubPer % per second. The delay is not restarted by later hits.
    4. If the gauge reaches 0 the status is deleted. If it reaches 100 the status becomes active, the gauge resets and the duration timer starts.
    5. While active, further applications do not stack damage. They only restart the timer (IsRefresh = 1 for every damaging status), so a steady stream of hits keeps a status alive forever.

    How often "an application" happens depends on the source:

    SourceBuild-up per application
    A hit from a move, a thrown weapon or a trick (explosion, fireball)StackAddPer once per hit
    A continuous area (a move's "period" damage, mud on the ground)StackAddPer × frame time, i.e. StackAddPer per second
    A trap (pool, rain, burning ground)StackAddPer 0.2 s after you enter, then once every 1 s while you stay inside
    Items and scripted effectsUsually instant (StackAddPer 10000)

    Families and replacement#

    StatusType groups variants into a family. When a new status arrives and another status of the same family is already on the target (AnimalBase:AddStatus):

    • If it is the same id: an active one is refreshed; a building one gets more build-up.
    • If it is a different id: the old one is deleted. Any partial build-up it had carries over into the new one. An already active status has 0 build-up, so its replacement starts from scratch. In other words, a different variant of the same family cancels a running effect and then has to build up again.
    • (An active old status that does not refresh would block the newcomer instead, but every damaging status in the game refreshes.)

    Damage over time formula#

    Every damaging status (kind 104, "PropertyPeriodSub") ticks once per second, starting on the first frame it becomes active. Each tick is:

    tick = ceil( (A × P2/1000 + P4) × 100 / (100 + R × P3/1000) + B × P5/1000 )

    • A: the attacker's damage of the status's AttackType (physical, fire, poison, ...). It is read once, when the first build-up lands, and kept for the whole life of the status, even if a different attacker later refreshes it. Statuses with no attacking character use a fixed number instead: a trick (fireball, flame, explosion) passes its own Damage, and so does a trap created by a trick (Holy Father's fireball ground, Edith's acid rain). That fixed Damage depends on the New Game Plus cycle (Damage_1...Damage_4; in the maze it depends on depth instead). Traps placed by a character's move use that character's damage.
    • R: the target's base resistance of the status's DefenceType. Base means level, talents, trophies and equipment. Temporary buffs and debuffs from other statuses are not included.
    • B: the target's own base value of the stat in Param1 (usually max HP). This is how "% of max HP" bleeds work.
    • On Casual the result is then × 0.65 when it hurts the player's HP, and × 0.5 while the player carries the Egg of the Bearer (item 10018).

    The number of ticks is roughly Time + 1, one on activation and then one per second until Time + 0.1 s has passed (inferred from the timer code).

    Stat debuffs (kind 102) use the same formula, but the result lowers the target's maximum of the stat in Param1 for as long as the status is active (see Corrosion).

    Resistance and immunity#

    • Nothing resists build-up. No stat, boss flag or difficulty setting reduces StackAddPer. Bosses fill the gauge exactly as fast as common enemies.
    • Guarding does not stop it. Statuses from a blocked or parried hit are only skipped if the row has GuardEnable. No row in the game sets it, so blocked hits still build Poison, Burn, Corrosion and Bleed (see Guarding, Parry and counter).
    • Resistance only lowers DoT damage, using the factor 100 / (100 + R). For the full direct-hit formula see Damage formula and Damage types and resistances.
    • Debuff immunity (status 10068 from Slightly Sweet Roots for 30 s, 10123 from Slightly Sweet Roots+ for 300 s) blocks any new status with IsDebuffer = 1. The check happens before build-up.
    • A few harmful statuses are not flagged as debuffs, so immunity does not block them and cleansing does not remove them: Viola's Abnormal-state "Wounded" (10004), the Marcion poison mist (10029) and the Treasure Thieves' defence-down (10110).
    • Marcion Puzzle Ball (trophy, logic 115 PierceMuteki) reduces the tick of any status with the piercing attack type to 0 on the player, which in practice means the Marcion poison mist.

    Hidden mechanics#

    • Resistance buffs do not reduce DoT damage. DoT ticks read base resistance, so Antitoxin Potion (+55 poison resistance) and Elixir of Inertia (+55 fire resistance) only reduce the damage of the poison or fire hit, never the poison or burn ticks. Trophies, talents and attribute levels do count.
    • Corrosion does not make DoTs hurt more. It lowers current physical defence, and DoTs read base defence. It does make every direct hit hurt more.
    • Burn is mostly reduced by physical resistance, not fire resistance. Burns 10008, 10037 and 10078 deal fire damage but use DefenceType 1 (physical). Only the knife burn (10012) and the Fireworks Barrel burn (10080) use fire resistance. See Burn.
    • The damage is decided by the first hit. The attacker's damage is read when the gauge first appears. Buffs or debuffs the attacker gets later do not change it, even after many refreshes.
    • A different variant cancels a running one. For example Viola's aimed-shot bleed (10001) and her red-bullet bleed (10034) are different ids of the same family: landing one on an enemy that is actively bleeding from the other ends that bleed and restarts build-up. Only 10001 is instant, so it re-applies at once.
    • Refreshes never stack damage. A bleeding enemy hit ten more times still takes one tick per second; the hits only push the end time back.
    • Item status talents also boost item side effects. The talents "Prolonged Duration" (ItemStatusTimeAdd) and "Improved Effect" (ItemStatusValueAdd) list Brute Force and Elixir of Epiphany among their items. Their self-inflicted defence-down and bleed therefore last longer, and that bleed hits harder, as the talents level up. See Bleed and Corrosion.
    • Norwood in the Abnormal state takes extra damage from non-physical DoTs: his resistance counts at 50% for the tick formula (Hero10004_Define.SanResistSubRate = 500). With "Adapt to Abnormality: Inertia" the cut becomes 30% / 10% by the code's arithmetic. The talent text says 40% / 20% (see Norwood talent tree, Lunatic state).
    • Invincibility does not stop ticks. Dodge invincibility and "invincible" buffs do not block damage over time. The kind-104 class has a check that would zero ticks while you are invincible, but the function that holds it (Status104:GetValueByPropertyId) is never called. The tick loop uses GetPropertyValue, which has no such check.
    • Shields soak ticks first. Each HP tick is taken from a skill shield, then from a trophy shield, before it reaches HP (see Shields and protection).
    • Some DoTs cannot kill. Rows with NotDeath (only the elixir side-effect bleeds 10086/10087) stop at 1 HP. Every other DoT can kill.
    • Debuff immunity first, elixir second. The side effects of Brute Force (10084/10085, defence down) and Elixir of Epiphany (10086/10087, self-bleed) are flagged as debuffs, but the attack buffs they come with (10057/10058, 10064/10065) are not. Use Slightly Sweet Roots first, then drink the elixir within 30 s (300 s with the + version), and you get the buff with no side effect. This follows from the immunity check in AnimalBase:AddStatus (not tested in game).
    • Trick and trap DoTs grow with New Game+. Ownerless sources use the trick's or trap's Damage for the current cycle. For example, the poison of tricks 10052-10054 uses A = 125 / 800 / 1000 / 1200 in cycles 1-4, so against 50 poison resistance the tick goes 24 → 82 → 98 → 115. In the maze the cycle is set by depth: below level 8 cycle 1, below 15 cycle 2, below 22 cycle 3, deeper cycle 4. Arcade mode always uses cycle 1.
    • Obsession Challenge: in the boss time challenge, any damage-over-time tick that you did not cause yourself (enemy, trick or trap) costs you the "perfect" result, just like a hit. Your own elixir bleed does not (see Obsession Challenge).
    • Nothing ticks on the hidden or the dying. Statuses are not updated while their bearer is hidden or dying, so no ticks happen. The duration is a clock time, though, so it keeps running: a status that ran out meanwhile is removed as soon as updates resume. (A real pause of statuses, PauseStatusAll, does extend the timers.)
    • The hero sanity effects start at the Abnormal state, not at Lunatic. Every hero-specific check used by statuses (IsHeroSanNotNormal) is true whenever sanity is not normal, i.e. from 70% sanity down (see Abnormal state, Lunatic state).
    • Benita's drug tolerance (Abnormal state) weakens statuses flagged DrugFast. No HP-damaging status has that flag. The only damage-over-time status with it is the Elixir of Hallucination's sanity drain (10074), and the effect is a 50% cut (Hero10003_Define.SanItemValueSubRate = 500) that applies while she carries one of three item statuses (10044-10046).
